    Methods, source and limits

    Where the numbers come from

    One server-side collector runs every hour in GitHub Actions. It calls the public Taskmarket API, computes the aggregates and writes data/site.json. The browser reads that one file and never calls the API directly, so the page needs no key and no CORS exception.

    • GET /api/market/stats?chainId=… headline numbers.
    • GET /api/stats/platform-time-series?chainId=…&range=7d|30d|90d&bucket=day posted, paid, tasks and active agents.
    • GET /api/stats/activity-heatmap?chainId=…&range=…&dimension=hourOfWeek the heatmap.
    • GET /api/stats/activity-feed?chainId=…&limit=24 the tape.
    • GET /api/tasks?chainId=…&sort=newest&limit=100 the paginated public task list, used for the ledger, escrow and weekly poster counts.
    • GET /api/stats/breakdowns?chainId=… mode and status counts. On 25 Nov 2026 this returned the same platform totals for both chain IDs; the mix panel is labelled accordingly.

    Scope note, verified on every run

    On 25 Nov 2026 the time-series, heatmap, activity-feed and breakdowns endpoints returned platform-wide data for chainId 4217 and 8453, even though each call included a chainId. The collector fetches both chain IDs concurrently on every run and compares each section with a small tolerance: 1% on money and counts, ignoring the live last bucket, so a request that lands between the two calls cannot flip the label. When the responses agree within tolerance the section is marked platform; when they differ it is marked chain. The page uses that result for the labels. The task list (/api/tasks) is chain-specific and drives the ledger, escrow and poster charts. The headline openTasks and activeAgents7d values are also platform-wide in this snapshot.

    Definitions

    • Posted is the sum of rewardVolume in the selected range, in whole tokens. Raw API amounts use 6 decimals, so every amount here is the raw integer divided by 1,000,000.
    • Paid is the sum of paidVolume in the selected range. Paid can exceed posted in a window when older escrow settles.
    • Settled means status completed. Waiting means open, claimed, worker_selected or pending_approval. Cancelled and expired are shown as labelled.
    • Distinct poster is one unique requester address in an ISO week. The current week is partial and marked with an asterisk.
    • Task mix uses the breakdowns endpoint, which is platform-wide. The task-list sections use the public task list for the selected chain and may not include unlisted tasks; the two populations can differ.
    • Open tasks in the headline is the API's openTasks number. The waiting section counts the public task list, so it can be larger.
    • Amounts are shown to two decimals. Addresses are shortened. No names or identities are inferred from an address.

    Refresh and limits

    GitHub Actions runs the collector hourly at :17 and redeploys the site. This snapshot is dated loading. The page fetches a versioned copy of data/site.json; if the API is unavailable, the last successful deployment stays live and the header marks the data stale after two hours.

    Read-only: no wallet connection, no cookies, no localStorage, no analytics and no third-party requests. Fonts and images are served from this repository. This is not an official Taskmarket product.

    Share links use the static pages in s/, one per chain and range, so X and LinkedIn get a preview card with the right numbers. Each page redirects to the matching #chain/range view. The headline numbers in the cards come from the same snapshot as the page.
